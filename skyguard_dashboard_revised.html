Hardware & Data Flow

Components of the SkyGuard payload and how data reaches this dashboard.

ESP32 Controller

Dual-core 240 MHz. Talks to the GPS and SIM800L over software serial (GPIO16/17 and GPIO26/27), reads the HC-SR04 on GPIO and builds a JSON packet every 5 s.

GPS Module (NEO-6M)

NMEA output at 1 Hz, 2.5 m CEP in open sky. Position, satellites in use and HDOP are sent in every packet.

Ultrasonic Sensor (HC-SR04)

Range 2 cm to 4 m, ~15° beam, sampled 5 times per second. Raises an advisory hazard alert below 1.5 m; it does not steer the drone.

GSM Module (SIM800L)

Quad-band 2G GSM/GPRS. Sends packets by HTTP POST and falls back to SMS for alerts when GPRS is unavailable.

System workflow

1. Geofence set-up: The operator draws the permitted flight area on the dashboard map.

2. In-flight telemetry: Every 5 s the payload sends position, fix quality, obstacle distance, battery voltage and GSM signal over GPRS.

3. Server checks: The PHP endpoint on Hostinger stores each packet in MySQL, tests the position against the geofence and checks the alert thresholds.

4. Operator alerts: Hazard, geofence, low-battery and link-loss alerts appear in the alert log; the operator decides what action to take.
